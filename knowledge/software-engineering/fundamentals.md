# Software Engineering Fundamentals

Git records changes as commits and supports collaborative branches. A useful commit contains one coherent change with a clear message. Pull requests enable review, automated checks and discussion before merging.

Unit tests check small pieces of logic, integration tests check components working together and end-to-end tests check complete user flows. Tests should be deterministic, isolated and focused on observable behavior.

Data structures organize information, while algorithms define the steps used to process it. Time complexity describes how running time grows with input size, and space complexity describes additional memory use.

Clean software separates responsibilities, validates inputs, handles expected errors and records useful diagnostics. Configuration and secrets should not be hard-coded. Documentation should explain setup, architecture, interfaces and operational limits.

Deployment should use reproducible builds and environment-specific configuration. Logging, health endpoints, monitoring, backups and rollback procedures help operators detect and recover from failures.
